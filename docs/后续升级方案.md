## 一、经历录入相关

### 1. 档3：工具内对话式录入（⬜ 未做）
- **背景**：档1（引导式表单）已砍、档2（采集提示词按钮）已做。档3 是让用户直接在工具里跟 AI 对话录入经历，不需要去外部大模型。
- **方案**：在「AI 智能导入」Tab 加聊天输入框，用工具自己的 DeepSeek 按采集提示词逐条追问用户，实时把解析结果写入经历库。
- **注意**：会消耗用户自己的 API Key 额度（用户已认可）；对话记录要可回放，别让用户重复录入。
- **优先级**：中。等档2 用一段时间、采集提示词验证稳定后再做。

### 2. 方案C：图片简历上传 OCR（⬜ 未做）
- **背景**：用户手里可能是图片/扫描件简历（含图片型 PDF），目前 import-file 只能抽 PDF/Word 文本，图片型 PDF 会返回"未能提取文字"。
- **方案**：接 OCR。`services/ocr_service.py` 已存在（pytesseract + chi_sim+eng），但需要本机装 Tesseract 二进制（当前未装，requirements 里只有 pytesseract 库）。
- **注意**：① 中文识别准确率依赖 Tesseract 训练数据，最好用 PaddleOCR/RapidOCR（中文更准）替代；② 图片简历格式最乱，解析正确率低于文本，导入后必须强提示用户逐模块检查。
- **优先级**：低。先保证文本导入稳。

### 3. 招聘信息截图批量导入（⬜ 未做）
- **背景**：用户曾设想把招聘软件上的 JD 直接截图发进工具。已有 `/api/ocr/extract` 接口（多图上传 OCR），但前端没接入，且依赖 Tesseract。
- **方案**：同方案C，OCR 能力落地后，在「简历生成」Tab 的 JD 输入区加"上传截图"按钮，OCR 结果自动填入 JD 输入框；多张截图拼接。
- **优先级**：低，依赖 OCR 能力。

## 二、简历生成与修改

### 4. 对话式 AI 修改（⬜ 未做）
- **背景**：现在「AI 辅助修改」是单次输入修改要求。用户希望改成对话式——在旁边开聊天窗口，针对简历某个模块多轮沟通修改。
- **方案**：对话窗口 + 支持用户圈选/指定模块（技能区/项目/教育等），后端用 revise_service 按模块级 prompt 修改，保留红绿 diff。
- **注意**：成本会上升（多轮对话），需限制轮数和范围；diff 展示已就绪可复用。
- **优先级**：中。

### 5. 匹配度分数优化（⬜ 未做）
- **背景**：当前 JD 匹配分数偏低（实测 62 分），用户反馈分数"感觉有点问题"，但暂不优化。
- **方案**：重新设计打分维度（关键词命中权重/经历相关度/行业侧重点），校准分数分布，避免"随便填也高分"或"好简历低分"。
- **注意**：分数是给用户看的参考，务必和"行业侧重点分析"联动。
- **优先级**：中。

### 6. AI 辅助修改"新增/删除模块"正式化（含回写经历库）（⬜ 未做）
- **背景**：2026-08-12 实测——AI 辅助修改已能"加自我评价 / 删校园经历 / 精简内容"，但有两个隐患：① 新增模块是 AI 模仿现有结构"碰运气"，标题/正文字体、class、顺序不保证每次对；② AI 修改只改当前这份简历 HTML，**不写回经历库**，重新生成后新增/删除都会还原（白改）。
- **方案**：
  1. 模板库维护"模块骨架"清单：每个模板各模块的标准 HTML 结构（含正确 class/字体），新增模块时后端从骨架注入，AI 只填内容、禁止动结构 → 字体/结构 100% 保证
  2. 「AI 辅助修改」加"➕ 添加模块"下拉（自我评价/兴趣爱好/培训经历等高频模块起步）
  3. 新增内容**同步回写经历库**对应表（自我评价→self_evaluation、兴趣爱好→other_info），删除时同步删经历库条目 → 重新生成不还原
  4. 插入位置固定（默认末尾），防打乱模板模块顺序
- **注意**：① 回写涉及"AI 写的内容 vs 经历库原数据"合并，需处理冲突；② 防编造是软约束，经历库空时 AI 可能写"做事认真负责"类万金油；③ 模板骨架库需随每个新模板维护。
- **优先级**：低。现有替代路径已够用：自我评价→经历管理填一句后重新生成；删/精简→AI 辅助修改直接做。

---

### 7. 简历「投递此岗位」跳转（⬜ 未做）
- **背景**：投递记录里"打开投递页面"目前只是记录 URL，无法直接跳转招聘平台（招聘平台不开放接口）。
- **方案**：① 引导用户从招聘软件复制 JD 链接，存到投递记录做溯源；② 后续可尝试爬取公开职位详情（合规风险需评估）；③ 最稳妥：只做"复制 JD 原文 + 打开招聘软件"的引导。
- **优先级**：低。当前定位是本地工具，"跳转投递"非核心。

## 三、公司调研与外部能力

### 8. 公司调研 Agent 小公司查不到（⬜ 未做）
- **背景**：公司速查/深度洞察依赖 DeepSeek 知识 + Dify Agent（公司调研工具链），小公司/初创公司数据量少经常查不到，当时因此没做自动化测试。
- **方案**：① 接入工商数据 API（天眼查/爱企查/企查查开放接口，有免费额度）做兜底；② 保留 AI 解读层，公司速查结果标注"数据来源/置信度"；③ 用公开站点检索兜底（如爱企查页面抓取，注意合规）。
- **优先级**：中。

## 四、工程与安全

### 9. 登录鉴权（⬜ 未做）
- **背景**：当前工具按"可暴露局域网/公网也安全"标准修过（路径穿越、CORS 收紧等），但无登录鉴权。
- **方案**：加简单口令登录（单用户场景够用），或用 FastAPI 的 OAuth2 密码流；敏感数据（简历/经历）落库加密。
- **优先级**：低。本地自用为主，如要公网部署才做。

### 10. 数据清理与备份（⬜ 未做）
- **背景**：`data/app.db` 当前含测试残留数据（education=2/internships=3/projects=3/skills=6/awards=2/other_info=4/basic_info=1），`/api/experiences/clear-all` 是测试专用接口（发布前要删）。
- **方案**：正式发布前删除 clear-all 接口；提供"导出全部经历 JSON/导入"备份功能。
- **优先级**：低。
