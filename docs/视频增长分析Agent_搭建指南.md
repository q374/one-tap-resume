# 视频增长分析 Agent · Dify 搭建指南（2026-08-18）

> 用途：给 AI 产品经理/助理面试当"真实 AI Agent 项目"讲。
> 数据源：你自己的抖音真实数据（33 条视频 + 3 天账号汇总 + 方法论）。
> 重点：这个 Agent 不是"工作流"，是**有目标、会拆任务、会调工具、有记忆**的真 Agent。

---

## 一、先说清：它和之前那个"简历检测工作流"有什么区别

| 维度 | 之前（简历检测工作流） | 现在（视频增长分析 Agent） |
|---|---|---|
| 应用类型 | Workflow | **Agent** |
| 有没有"目标" | 没有，纯按固定流程跑 | 有，系统提示词里写死"帮账号主理人定位问题→给优化方案" |
| 能不能自主拆任务 | 不能，节点写死顺序 | 能，模型自己按 SOP 决定先干啥后干啥 |
| 会不会调工具 | 只会接一个知识库 | 会自己选：代码执行 / 知识检索 / 联网搜索 |
| 记不记得上一句 | 不记得，每次无状态 | 记得，多轮对话上下文自动保留 |
| 输出 | 固定两段文本 | 可边想边查边算，多轮追问 |

一句话：**工作流是"流水线"，Agent 是"有脑子的员工"。**

## 二、四大能力分别体现在哪（面试讲稿）

### 1️⃣ 目标（Goal）——写在系统提示词第一段
系统提示词里直接写死：
```
你的目标是：帮账号主理人从抖音真实数据里定位问题、验证假设、产出下一期可执行的优化方案。
每次回答必须回到这个目标，禁止只列数据不给结论。
```
→ 面试时讲：Agent 的"目标"不是 UI 上有个按钮，而是**写进系统提示词的角色约束**，它所有行为都围绕这一个目标展开。

### 2️⃣ 自主任务拆解（Task Decomposition）——写在系统提示词的分析 SOP
系统提示词里内置一套固定分析套路（Agent 会自己按步骤推进）：
```
收到数据后，按下面 5 步走，每步做完再进下一步：
Step1 取数：先读用户给的数据（或调用代码工具读 csv）
Step2 算指标：算播放/完播/2s跳出/5s完播的环比、TOP、最低
Step3 对比：和合格线比（2s跳出≤45%、5s完播≥25%）
Step4 归因：结合方法论知识库找原因（开头钩子/时长/标签/封面）
Step5 建议：输出 1-2 条下周可执行动作
```
→ 面试时讲：任务拆解不是写死在节点图里，而是**用提示词约束模型自主规划执行顺序**，模型会根据实际情况决定要不要多算一步。

### 3️⃣ 工具调用（Tool Use）——Agent 节点里挂 3 个工具
| 工具 | 干什么用 | Agent 什么时候自己调它 |
|---|---|---|
| Python 代码执行 | 读 csv、算环比、TOP N、找 BadCase | 用户说"分析这周为什么跌" → 先算数据 |
| 知识检索（方法论库） | 查"数字钩子/时长/标签"经验 | 归因阶段 → 调出来对答案 |
| 联网搜索（可选） | 查最新抖音规则/热点 | 用户问"标签会不会限流" → 去搜 |
→ 面试时讲：Agent 的**工具调用是模型自主决策**的，不是固定脚本。它觉得需要算就会调代码，需要经验就会调知识库——这就是"工具调用"和"流程里放个节点"的本质区别。

### 4️⃣ 记忆（Memory）——Agent 类型自带
多轮对话示例：
- 第一轮：你问"分析我最近视频为什么跌"
- Agent 回答后你说"那下次标签少点"
- 第二轮你问"那我封面要不要改"
→ Agent 会记得你刚才说过"标签少点"，回答会结合这条上下文，不会失忆。
→ 面试时讲：记忆 = **多轮上下文保留**，让 Agent 像真人同事一样记得之前的讨论，不用每轮重复交代背景。

## 三、搭建步骤（本地 Dify，你已有 Docker）

### Step 1 新建应用
1. 本地 Dify → 右上角「创建应用」
2. 应用类型选 **Agent**（⚠️ 不是 Workflow，Workflow 没有记忆和自主工具调用）
3. 命名「视频增长分析 Agent」

### Step 2 配模型
- 模型选你已有的 **v4**（你的 key 是第三方平台，模型名选 v4/pro 即可，没有 deepseek-chat 是正常的）

### Step 3 写系统提示词（整段粘贴）
```
你是资深抖音内容增长分析师，服务对象是一个用 AI 流水线做简历工具宣传的账号主理人。

【你的目标】
帮主理人从真实数据里定位问题、验证假设、产出下一期可执行的优化方案。每次回答必须回到这个目标，禁止只列数据不给结论。

【你手上有三份资料】
1. 抖音方法论知识库：从真实 A/B 复盘里沉淀的规律（数字钩子>口号、开头3秒高光、2s跳出≤45%等）
2. 视频数据：videos.csv（33条视频：标题/分类/日期/播放/完播/5s完播/2s跳出/互动）
3. 账号汇总：account_summary.csv（8-14/8-15/8-16 三天的播放/完播/2s跳出）

【分析 SOP，每步做完再进下一步】
Step1 取数：读用户给的数据，必要时调用 Python 代码工具
Step2 算指标：算环比、TOP N、最低表现、分类均值
Step3 对比：和合格线比（2s跳出≤45%、5s完播≥25%）及方法论结论
Step4 归因：结合知识库找原因，区分"内容问题"和"账号问题"
Step5 建议：输出 1-2 条下周可执行动作，每条写明预期效果

【注意】
- 只基于真实数据说话，没有数据支撑的判断要标注"推测"
- 排除噪音：打卡记录/无关主题要单独剔除，别混进主账号分析
- 回答用中文，结论放最前面，数据做支撑
```

### Step 4 挂工具
1. **知识检索**：右上「添加功能」→「知识库」→ 新建「抖音方法论」库，上传 `D:\video-workflow\抖音数据\Agent数据集\视频方法论.md`
2. **Python 代码执行**：Agent 工具列表里加「代码执行」；演示时把 videos.csv 内容直接粘贴给用户当输入，或把 csv 也传进知识库当文档
3. （可选）联网搜索：Dify 需要配搜索 API，没有就先不加，不影响演示

### Step 5 数据给谁用
- **方法论** → 知识库（RAG 检索）
- **videos.csv / account_summary.csv** → 推荐把 csv 内容也作为文档传进知识库（Dify 支持 csv 作为知识库文档），Agent 检索时能拿到；精确计算时它自己会调代码工具

### Step 6 演示场景（直接照这个问）
> "分析我 8 月 16 日播放为什么跌到 146，给下周 3 条优化建议"

Agent 会：Step1 读数据 → Step2 算出 8-16 播放 146（比 8-15 的 377 跌 61%）→ Step3 对比合格线 → Step4 调方法论知识库归因（2s跳出 66% 超线、封面/开头没高光）→ Step5 给建议。

## 四、演示时的面试话术（背下来）

> "我这个 Agent 的核心不是'分析数据'，而是**用 Agent 架构解决'数据→决策'的最后一公里**：
> 目标写进系统提示词、任务靠 SOP 自主拆解、数据靠工具调用拿、上下文靠记忆保留。
> 它和市面上一键报表工具的区别是：报表只给你数字，它给你**带归因的决策建议**。
> 这正好对应哈啰那个岗位——'构建业务 Agent：取数→异常诊断→报告生成'。"

| JD 要求（哈啰/八爪之鱼/语核/蓝色光标/领健） | 这个 Agent 怎么证明 |

| 数据分析 | 真实抖音数据，环比/TOP/BadCase 全做了 |
| 产品闭环思维 | 数据→诊断→建议→下期验证，完整闭环 |
